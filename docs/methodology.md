# III. Methodology

## A. Overview
This study develops and validates the **Technology Leverage Score (TLS)**—a composite index designed to quantify how technology substitutes for labor, capital, and expertise in early-stage venture creation.  
The TLS provides a standardized measure of operational leverage generated by automation, software tools, and digital infrastructure.  
All computations are implemented in the **tech-leverage-tls** repository, which automates data intake, preprocessing, computation, and validation.

---

## B. Data Collection and Structure
Data were collected through a structured survey distributed to entrepreneurs, startups, and small businesses.  
Each respondent supplied quantitative and categorical inputs representing monthly operations.

| Category | Example Variables | Description |
|-----------|------------------|--------------|
| **Labor** | `employees_fte`, `monthly_labor_hours_2025_total` | Human input intensity |
| **Capital** | `capital_invested`, `annual_tech_spend` | Traditional capital intensity |
| **Technology** | `tech_tools_list`, `tools_frequency_of_use`, `p_auto` | Digital enablement indicators |
| **Performance** | `monthly_revenue_2025_*`, `profit_margin_percent` | Output and productivity proxies |

Responses were captured in a **Google Form**, synchronized to a **Google Sheet**, and exported as a `.csv` file for ingestion by the analysis pipeline.  
Raw files are stored in `/data/raw/`, and processed outputs are written to `/data/processed/`.  
This ensures version control and full reproducibility.

---

## C. Computational Framework
The TLS is computed as a weighted function of three primary constructs:

1. **Automation Leverage (A)** – reduction in labor input through process automation.  
2. **Tool Leverage (T)** – augmentation of human productivity via AI and software tools.  
3. **Capital Leverage (C)** – substitution of digital assets for traditional capital inputs.

\[
TLS = \alpha_1 A + \alpha_2 T - \alpha_3 C
\]

where the coefficients \(\alpha_1,\alpha_2,\alpha_3\) represent empirical weights derived from model calibration.  
In the baseline implementation:

\[
TLS = 2A + T - 0.5C
\]

The computational logic resides in `src/tls_metric/tls_calculator.py`,  
which accepts a structured DataFrame and returns a normalized TLS value per firm.  
Validation tests in `tests/test_tls_calculator.py` confirm numerical consistency within \(10^{-6}\) tolerance.

---

## D. Data Processing Pipeline
The end-to-end workflow operates as follows:

1. **Data Intake** – Raw survey responses are loaded via `scripts/run_pipeline.py` using `data_loader.py`.  
2. **Pre-processing** – Missing values are imputed, variables standardized, and categorical fields encoded.  
3. **TLS Computation** – `compute_tls()` applies the core formula to each record.  
4. **Summary Statistics** – Aggregated metrics (mean, SD, min, max) are output to `/results/summary_stats.csv`.  
5. **Validation** – Automated Pytest routines ensure reproducibility before committing results.

All stages are modular, enabling future refinement or alternative weighting without disrupting other components.

---

## E. Reproducibility and Transparency
To ensure reproducibility and transparency, the repository includes:

- **Unit tests** for all computational modules  
- **Pre-commit hooks** for syntax and formatting  
- **Structured documentation** in `/docs/`  
- **Continuous integration** via GitHub Actions (`.github/workflows/test.yml`)

This infrastructure guarantees that every finding can be reproduced directly from the source code and dataset under version control.

---

## F. Output Interpretation
The resulting TLS values, stored in `/data/processed/with_tls.csv`, quantify each firm’s **technology-derived operational leverage**.  
Higher TLS values indicate greater substitution of technology for traditional inputs and therefore greater scalability and efficiency.  
These scores are later correlated with firm-level performance measures (revenue growth, labor efficiency, profit margin) in the Results section.
